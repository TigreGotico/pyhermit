# Decisions: Finish the pyhermit Port

| Decision | Alternatives Considered | Rationale |
| :--- | :--- | :--- |
| Vendor owlapy model layer into `hermit/owl_model/` rather than taking it as a runtime dep | (a) `pip install owlapy`; (b) write bespoke OWL type layer from scratch | owlapy's `owl_ontology.py` imports `jpype` at module level — making it a dep would drag in JVM tooling. Vendoring the 10 pure-Python model files (~4,400 lines) gives us the full OWL type hierarchy with zero new external deps and no version-drift risk. Writing from scratch would be ~equivalent effort with no benefit. |
| Replace `pandas.Timedelta` with `datetime.timedelta` in vendored `owl_literal.py` | Keep pandas as an optional dep; use a shim | pandas is a heavy dep for one duration type. `datetime.timedelta` covers the same ISO 8601 duration use case. Only `parse_duration()` and `DurationOWLDatatype` handling need adjustment — trivial change. |
| Implement a minimal inline `_Automaton` class for ObjectPropertyInclusionManager | (a) `pip install automaton` / `pip install dk.brics.automaton`; (b) use `networkx` DiGraph | No Python package replicates the Java `rationals.Automaton` API exactly. The ObjectPropertyInclusionManager only needs: add_state, add_transition, initial state, final states, and accept-word check. An inline 60-line NFA class is simpler and avoids a new dep. networkx is overkill and another heavy transitive dep. |
| `OWLNormalization` accepts `Iterable[hermit.owl_model.OWLAxiom]` (vendored types) | Accept owlready2 objects directly; accept hermit.model types | owlready2 types would couple the normalization layer to the parser. hermit.model (internal DL types) are post-normalization — they can't represent raw OWL axioms. The vendored OWL model layer is the right abstraction boundary matching the Java OWL API contract. |
| BuiltInPropertyManager and ObjectPropertyInclusionManager mutate `NormalizedAxioms` in-place and are called from `OWLNormalization.process_ontology()` | Call them from `OWLClausification.clausify()`; make them return new `NormalizedAxioms` | Java HermiT calls them from inside `OWLClausification`, but the mutation pattern fits better in `process_ontology()` where `NormalizedAxioms` is constructed — clausification is already handling enough. Mutation is fine since `NormalizedAxioms` is built fresh per ontology. |
| `owlready2` is an optional dep (import guard in `hermit/parser.py` only) | Make it a required dep in `pyproject.toml` | Keeps the core reasoner importable in pure-Python environments where no ontology file parsing is needed (e.g., when `DLOntology` is constructed programmatically). Consistent with current zero-dep design in `pyproject.toml`. |
| Fix `apply_dl_clauses` by dispatching on `m_tuple_arity` of the extension table | Add a separate retrieval list for binary vs ternary | The extension table already tracks `m_tuple_arity` (2 for concept, 3 for role). Dispatching on it is the most direct fix matching the Java source which uses separate `ExtensionTable` instances with known arities. |
| DatalogEngine uses `NullExistentialExpansionStrategy` (no-op) during materialization | Use the full existential strategy | Matches Java exactly. Datalog evaluation operates on the ground ABox only — existential expansion would generate tree nodes that are not needed for conjunctive query answering over named individuals. |
